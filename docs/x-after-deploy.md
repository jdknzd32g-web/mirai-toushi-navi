# デプロイ後のX自動投稿

更新：毎日のブログ公開までユーザー承認済み。現行の公開順序は`docs/daily-publishing.md`を参照。下記の公開権限に関する制限は日次フローに限り変更済みで、公開チェック・重複防止・SBI除外は維持する。

2026-09-13の指示により、公開済みの非SBI記事を @ryo20230917 に各1回投稿する。毎朝の記事生成が本番公開を自動的に許可するわけではない。

## 実行順序

1. 承認済みのブログをデプロイし、本番のデプロイIDを照合する。
2. `editorial/published-releases.json`へ対象記事ID・URL・デプロイID・パッケージのパスを記録する。
3. 対応パッケージに対する`verify_release.cjs --production`を実行する。追加バッチでは`RELEASE_BATCH=additional`を指定する。将来のバッチは対応するリリース検査・出力先を用意する。
4. 本番検査が合格したときだけ`post-published-x.cjs --send`が呼ばれる。検査失敗では呼ばれない。

記録が検査後に作られた場合やPCが停止した場合は、15分ごとの公開後フォローが未投稿を拾う。既存のリリースツールは2バッチ固定のため、将来の公開は必ず正しい対象パッケージと検査結果を作ること。公開チェックを省略して投稿しない。

公開後フォローは既存の定期実行`sbi-nisa-1`に統合済み。15分ごとに起動するが、記事作成は日本時間9時以降の当日未完分だけ。週次休息通知も従来どおり日曜に1回。別の重複スケジュールは作成していない。ローカルPCとCodexが稼働している必要がある。

## 防止策

- published記録、対象記事の本番検査合格、HTTP公開状態を要求。
- パス・タイトル・カテゴリにSBI/ＳＢＩが含まれる記事は除外。
- 本文投稿は原稿のdescription（未設定時はtitle）のみを使用し、記事URLを入れない。記事URLは必ず最初の自己リプライへ掲載する。長文は文字数内に切り詰め、成果保証などの表現を追加しない。
- 本文投稿とURL付きリプライの両方を読み戻し、リプライが本文投稿を参照していることまで確認してからverifiedにする。
- `editorial/x-published-results.json`と2026-09-13の既存投稿記録、直近100件のX投稿を照合。
- 送信前にsendingを記録し、送信結果不明・読み戻し失敗は自動再送しない。確認してから手動で整合する。
- 多重実行は排他ロックで停止。クラッシュ後のロックはプロセス終了と投稿履歴を確認するまで削除しない。
- 本番確認済み記事の投稿状態だけ処理し、コードや記事の自動デプロイ・課金設定の追加はしない。

安全な検査：`node tools/blog_pipeline/test-post-published-x.cjs`、`node tools/blog_pipeline/post-published-x.cjs`（投稿しない）。
